# Changelog

All new releases use [Semantic Versioning](https://semver.org/) and Conventional Commit subjects. Dates refer to the tagged source release, not to any claim that a neural student has qualified new capabilities.

## [0.3.0] - 2026-10-25

### Added
- Teacher vNext shadow proposal control with portable learner-region, proposal, outcome, health and multi-fidelity evidence contracts for the future divergent teacher implementation.
- Full direct-U7C Grade B Boolean teaching coverage with bounded complete B revisit passes while Grade C remains the progression frontier.
- Continued factory-owned Grade C numeric staircase, including explicit numeric-root scope transitions and dashboard milestones.
- Run-owned software-version provenance on session-start telemetry and dashboard display, so detached observers can identify the trainer version that produced the active run.
- Bounded host-side source-prefetch workers while keeping MLX inference, student weights, AdamW, retention, scheduling and persistence serialized on the sovereign neural lane.

### Changed
- Teacher strategy selection now conditions on contextual retention evidence, rejection pressure, realized lesson delivery and learner state rather than treating historical policy success as stationary.
- Teacher vNext learner regions preserve bounded active-grade score topology, mastery-debt shape and differentiated high-pressure bands without using checkpoint SHA as predictive identity.
- Scheduler treatment of nongating Grade B debt uses bounded full-grade turns instead of allowing Boolean debt to monopolize the progression run.
- Dashboard presentation now surfaces active integer-root scope, current run identity and the SemVer software version separately from curriculum/profile version labels.

### Fixed
- Repeatedly failing effective policies are temporarily retired for the exact unchanged student checkpoint, while historical evidence is preserved and the policy automatically reopens after retained student change.
- Candidate-retention and teacher-control paths avoid several rejection-only novelty loops, stale-geometry pressure, ineffective strategy variants and misleading operator states discovered during live Prometheus recovery.
- Promotion/debt liveness, Grade C continuation, direct-U7C fragile replay and active-strategy population handling no longer strand otherwise valid training progress.
- State/data-plane and MLX runtime hot paths avoid several avoidable copies, cache growth, stale soup retention and dashboard DAG-read inconsistencies.
- Python package version metadata now agrees with the project and npm manifests and is enforced by `release:check`.

### Retained
- Source-oracle truth, candidate-retention gates, student/own-AdamW custody, championship authority, promotion requirements and human ownership of real neural training remain unchanged by the new teacher observability and versioning surfaces.
- Exact checkpoint, batch and cohort identities remain provenance rather than Teacher vNext generalization keys.

### Limitations
- Teacher vNext remains shadow/evidence infrastructure until separately activated; its presence in `0.3.0` is not evidence that the live student has been trained by the divergent teacher.
- A process started from an older source release cannot hot-load this version. Its historical dashboard can only display run-owned software version when that older runtime recorded the field.

## [0.2.0] - 2026-10-17

### Added
- One canonical `bilqis-mlx` source checkout with pinned, locally vendored historical source oracles, teacher policy and the original bootstrap checkpoint kept out of Git.
- Whole-student, own-AdamW retention peaks across comparable curriculum cohorts and a tighter recovery-stage harmful-candidate gate.
- Configurable ignored `BILQIS_STORAGE_ROOT`, with retained checkpoint bundles and human-operated resume.
- Source-grounded Grade C numeric staircase, typed mentor soups, contextual teacher outcomes and append-only semantic registry growth.
- Reproducible, checksum-verified state lineage migration; bounded, lossless JSON generation compaction at normal stop boundaries.
- Release metadata, Conventional Commit validation, change recording and gated automation adapted from the reference Bilqis repo.

### Fixed
- Frozen soups partition incompatible historical vocabulary generations rather than averaging differently shaped tensors.
- Actual vocabulary metadata now follows the admitted semantic graph while protecting the immutable historical token prefix.
- Finder-generated `.DS_Store` files no longer interrupt checkpoint custody; unknown files and symlinks still block retirement.
- Resume repairs retain the original model and optimizer and do not mistake a provisional retention gate pass for graduation.

### Retained
- Existing complete student and native AdamW optimizer, historical teachers/champions and their provenance, original source-checkpoint SHA, preserved curriculum rubrics and all verified historical state before any archive retirement.
- Strict human ownership of actual training. No new neural runs are started by CI, tests or migration helpers.

### Limitations
- Whole-student retention peaks are historical custody references, not automatic student rollback or independently proven long-term protection.
- Old worktrees and prior checkpoints remain as recovery copies until independently verified external archival is possible.
- MLX-specific neural functionality requires Apple Silicon; portable CI does not assert that GitHub's Linux workers trained a student.
