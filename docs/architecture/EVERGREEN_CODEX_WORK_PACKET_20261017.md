## Sequencing and proof doctrine

1. **Inventory, not reinvention.** Verify live authority and current code; produce a compact verified-vs-missing Q01-Q10 matrix. Distinguish required long-term policy from source-only scope. Record early discovered reusable bugs in the existing private incident process without duplicating old incidents.
2. **First independently verifiable release spine:** turn evidence-looking strings into bounded authentic receipts tied to exact source bytes/revisions, source support, semantic/catalog release and parent. Introduce explicit `UNKNOWN`, `BLOCKED`, `READY_FOR_INDEPENDENT_REVIEW`, `ADMITTED` boundaries. A syntactically plausible `repo:` or `https://` string is not proof. Preserve prior valid releases. Keep authority signoff separate from checker output.
3. **One unfamiliar synthetic-semantic vertical slice:** compile its positive definition (type/world/arity/source/qualification), independently mastered prerequisites, minimal staged teaching, generated instruction and independently checked probe cases via existing AST/adapter/proof stack, plus affected-family regeneration. No hard-coded letter or hand-built specimen bank. Only then generalize the admission path from C-specific to future grades.
4. **Selection and recursion:** use sourced alternatives and observed existing mastery/retention/coverage to prepare candidates, including early foundations for future grades. Record concrete near-term payoff, source/donor license/commit, neural-vs-codec reason and explicit uncertainty. History provides hypotheses, not selection.
5. **Quality, continuity, observable health:** wire proportionate fast CI and release verification. Add human-attention and quarantine proposals as read-only/disposable shadow instruments with falsifiable replay tests. **Do not silently change the active adaptive teacher, student, candidate acceptance, optimizer or run behavior.** Graduate the proposal only through a separate authorized decision backed by measured benefit.

Across all phases, the three original semantic-function families are **non-exhaustive**. **Identification** is each primitive's *positive* prerequisite-grounded intrinsic meaning and operation. **Association** retrieves potentially applicable meanings from an expression; **disambiguation** uses increasingly broad contextual evidence to narrow them. No three placeholder NLP functions per maths primitive. The v2 planning dispositions (`DEFERRED`, `FOUNDATIONAL`, `REQUIRES_QUALIFIED_IMPLEMENTATION`) do not certify executable interpretation or neural mastery.
