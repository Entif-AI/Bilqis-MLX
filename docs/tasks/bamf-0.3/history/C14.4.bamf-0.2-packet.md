# C14.4 | Admit untrusted asynchronous swarm learning contributions

**BAMF-0.2 implementation packet. Lane C.** Full original owner: [C14 #386](https://github.com/Entif-AI/Bilqis-MLX/issues/386); direct native parent: [C14 #386](https://github.com/Entif-AI/Bilqis-MLX/issues/386). **This issue owns the public/remote contribution boundary, not synchronous local distributed training.**

## Outcome

Allow heterogeneous community-owned machines to contribute useful BAMF learning/evaluation work asynchronously while one canonical school retains sole authority to admit state.

Workers may propose learning. They do **not** unilaterally teach the canonical student.

## Direct prerequisites

- [B13 #372](https://github.com/Entif-AI/Bilqis-MLX/issues/372) complete generation persistence/cold resume.
- [C05 #378](https://github.com/Entif-AI/Bilqis-MLX/issues/378) retention/admission safeguards.
- [C12 #381](https://github.com/Entif-AI/Bilqis-MLX/issues/381) bounded capability/plastic delta packaging where applicable.
- Local tightly coupled multi-device execution is owned by C08.4, not this issue.

## Parent context (not a blocking direct prerequisite)

[C14 #386](https://github.com/Entif-AI/Bilqis-MLX/issues/386) continuing developmental program.

## Contribution contract

A remote work manifest must bind at minimum:

- content-addressed retained checkpoint/generation identity;
- exact source/curriculum release and capability assignment;
- deterministic seed/work partition;
- permitted training/evaluation budget;
- model/topology/MLX implementation identity;
- source/rights scope;
- expected artifact type;
- acceptance/evaluation contract;
- expiry/replay identity.

A worker returns content-addressed artifacts plus receipts, never a claim that canonical state has already changed.

## Initial contribution classes

The first release SHOULD prefer contributions with clean composition and independent verification:

1. evaluation/challenge cohorts and retention batteries;
2. source/curriculum construction and counterexample discovery;
3. candidate training branches against a frozen parent;
4. bounded adapter/plastic deltas whose ownership and affected parameter sets are explicit;
5. motif/semantic-memory candidates with explicit allocation ownership;
6. regression, parity and capability qualification evidence.

Arbitrary independently optimized dense model updates MUST NOT be naively added, averaged, merged or promoted without a separately specified and verified aggregation algorithm.

## Trust and admission

1. Treat every external node and returned artifact as untrusted.
2. Verify manifest identity, digests, source/rights scope, topology compatibility and replay/freshness before evaluation.
3. Re-evaluate learning claims against independent canonical-school cohorts. Worker-provided labels/scores are evidence, not authority.
4. Admission passes through the same retained-candidate/rollback/correction safeguards as locally produced work.
5. A rejected contribution may retain observational value but cannot mutate canonical weights, optimizer state, motif allocation, semantic activation or teacher history.
6. A public node never receives credentials or mutable authority unnecessary for its bounded assignment.

## Acceptance

- [ ] A disposable remote-worker fixture can receive a frozen work manifest and return a signed/content-addressed candidate receipt without writable access to canonical state.
- [ ] Replaying, modifying or returning a result for the wrong generation/source release is rejected.
- [ ] At least one non-neural contribution class and one bounded learned-candidate class can be independently verified and either admitted or rejected by the canonical school.
- [ ] A malicious/incorrect worker score cannot bypass independent retention/admission evaluation.
- [ ] Candidate rejection leaves canonical neural, optimizer, motif, semantic and teacher state unchanged.
- [ ] Contribution receipts preserve enough environment identity to reproduce/explain materially different results across heterogeneous Apple/CUDA workers.
- [ ] Dense-update combination remains fail-closed until an explicit aggregation algorithm and conformance proof exist.
- [ ] The continuing C14 program can opportunistically dispatch eligible bounded work to the swarm without making swarm availability a prerequisite for local training.

## Non-goals

No cryptocurrency/mining mechanism, no incentive economics, no global synchronous SGD, no trust-by-membership, no automatic public release of private source material, and no assumption that all contributors own identical hardware.

## Turn-in

Follow the Lane C lifecycle in parent #386. Use public/synthetic fixtures for distributed-protocol tests; do not expose protected source material. Live optimizer starts and final canonical admission remain under existing authority.
