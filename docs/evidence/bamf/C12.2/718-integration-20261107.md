## Authority chain

The production entry point is
`cognitive_package.operator.receive_screen_and_publish_package(...)`.
It composes existing owners in this order:

1. C12 derives the receiver binding from the current B13 generation and receives one
   bounded local package through `receive_package(...)`.
2. A12/C09 verifies the signed `ExportClearanceReceipt` against the current Atlas
   selection, source frontier, authority registry, exact artifact set, rights epoch,
   correction generation, and receiver correction frontier.
3. B12 creates the package-import transaction from the current accepted parent. The
   fixed reset policy changes only declared slices and resets the owned optimizer
   state for those slices without importing sender optimizer state.
4. C05 evaluates the B12 transaction through `evaluate_factory_package_import(...)`
   and issues the retention decision. The caller cannot supply policy, cohorts,
   evidence, or an acceptance Boolean.
5. C12 re-reads the current parent and A12/C09 authority before B13 publication.
   B13 mints the acceptance binding from the owner-issued C05 decision and records a
   `PACKAGE_IMPORT` generation transition.

`SourceRights` remains a portable projection. Matching package-local fields do not
authorize export or publication. C05 eligibility also does not publish a generation.
