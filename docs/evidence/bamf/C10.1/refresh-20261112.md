## Current production seam

The earlier C10 implementation landed through PR #550 and current reviewed unified
already contains the append-only Akasha outbox, durable domain binding, native
generation projection, Rosetta Observation bridge, and staging projection.

Since that work landed, C07/B13 added the production Factory-release adoption event
`BAMF_FACTORY_RELEASE_ADOPTION_COMMITTED`. Its authority is stronger than an event
name: B13 validates one exact owner event shape against the accepted Factory-release
admission binding, transition digest, release provenance, run/generation identity,
optimizer step, and immutable outbox lineage.

C10's current native adapter does not yet consume that B13 historical acceptance
binding. It therefore must not assign `FACTORY_RELEASE` semantics merely because a
record carries the new event name. This refresh pins that fail-closed boundary in a
regression: even a lookalike carrying all four C10 timestamps remains uncovered
until the B13 owner authority is consumed.

The production event also currently lacks explicit `source_time`, `effective_time`,
`observed_at`, and `recorded_at` values. C10 must not infer those values from
generation number, filesystem metadata, observation order, or wall clock.

## Proof boundary

The focused generation-projection regression now covers three cases:

- a known, already-authorized teacher event still projects normally;
- a timestamped `BAMF_FACTORY_RELEASE_ADOPTION_COMMITTED` lookalike remains in
  `uncovered_native_event_ids` because C10 has not authenticated B13 owner authority;
- the same event name without complete time authority also remains in
  `uncovered_native_event_ids` and does not enter the projection outbox.

No C07/B13 event shape, accepted generation, lease, learner, optimizer, source
rights, graph service, or persistent runtime state is changed by this patch.
