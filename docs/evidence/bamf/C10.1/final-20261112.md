## Time semantics

The controlling C10 contract requires source/effective/observed/recorded times
**where relevant**. The previous v1 implementation accidentally required all four
integers for every event, which forced non-temporal production owners into synthetic
receipt fixtures.

`bilqis.c10.akasha-event/v1` now accepts exactly two temporal states:

- all four fields are explicit nonnegative integers; or
- all four fields are explicit `null` when the owner does not provide those clocks.

A partial quartet is invalid. No generation number, filesystem timestamp, journal
position or wall clock is substituted for missing owner time. Existing timed-event
canonical bytes and IDs are unchanged.

Unknown-time events remain local/internal under the current C10.3 public schema.
`bilqis.c10.public-event/v1` still requires concrete times and therefore rejects
these events before public staging. Rosetta Observation signals preserve explicit
`null` values rather than fabricating measurements.
