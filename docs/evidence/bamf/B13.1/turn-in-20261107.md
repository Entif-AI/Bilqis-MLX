## B13.1 defects repaired on this branch

1. **Malformed compiler feature bindings escaped the ErrorBus.**
   `feature_source` or `feature_schema` with a malformed recorded value could call an undefined `invalid` name and raise raw `NameError`. The validator now receives the caller's B13 invalidation function explicitly. Save and rehashed cold-load regressions prove malformed bindings fail through the typed boundary before unsafe tensor work.
2. **Acceptance receipt durability was incomplete.**
   Receipt bytes were fsynced, but the containing `bamf-acceptance` directory was not fsynced before generation pointer publication. The publication owner now fsyncs that directory after new receipt installation and on the existing-receipt retry path.
3. **EGM round 3 exposed a deeper first-publication ancestry gap.**
   Newly created `bamf-bundles` and `bamf-acceptance` directory entries were not guaranteed durable in their parent `run_dir` before `_atomic_pointer()` could install the generation pointer. The repair now fsyncs each newly created custody directory and then `run_dir`, matching the repository CAS durability pattern.
4. **EGM round 4 exposed the genesis run-root ancestry gap.**
   `_require_run_root()` could create a missing nested `run_dir` and fsync the contents below it without durably committing the new run-root directory entries into their parents. The repair records the missing chain before creation, fsyncs every newly created directory, and then fsyncs the first pre-existing ancestor before pointer publication. The regression places the data plane under a separate temporary parent so CAS fsyncs cannot accidentally satisfy the B13 run-root ordering witness.
5. **EGM round 4 exposed an accepted-state authority bypass.**
   `load_bamf_generation_authority()` and `admission.load_accepted_generation()` could authenticate pointer and bundle custody while never authenticating the `bamf-acceptance/<manifest>.json` receipt bound by `acceptance_sha256`. A missing or re-signed-but-drifted acceptance record could therefore still yield a value described and consumed as current accepted B13 authority. One shared `_require_published_acceptance()` owner now verifies receipt presence, schema/digest binding, run/generation, feature identity, optimizer step, candidate identity and step-proof identities before either accepted-authority loader returns. `admission._published_in_memory_identity()` reuses the same owner instead of maintaining a second copy of the acceptance logic.
6. **Cold-resume negative test carried a superseded B11 diagnostic identity.**
   The regression expects the accepted `B11_GRADIENT_EXECUTION_REQUIRED` failure while preserving fail-closed behavior. No B12 runtime behavior changed.

The earlier defects are logged as `PM-2026-11-07-001` in the Entif Post-Mortem Ledger. EGM round 3 is recorded on #478. No real learner, AdamW, teacher, source promotion or durable production generation was mutated during repair or verification.
