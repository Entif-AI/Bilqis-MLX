## Problem and resulting behavior

The handoff helper previously stopped before writing JSON when a local feature
branch had no configured upstream. That lost the branch, local commit and dirty
file fingerprint even though those facts were available. The preserved #810
worktree reproduced this failure; no files in that worktree were changed.

`scripts/bamf/writer_handoff.py` now obtains the configured upstream through
`git for-each-ref`. When none exists, it still records the resolved worktree,
branch, HEAD and content-sensitive dirty fingerprint. The v1 JSON has explicit
`null` values for `upstream` and `observed_remote_head`, with
`status: "UNVERIFIED"` and `reason: "NO_UPSTREAM"`.

Emission exits 0 after writing JSON to stdout; caller redirection saves the receipt. Verification
of the same local-only snapshot prints the same unverified disposition and exits
**2**, so it cannot be mistaken for a successful remotely verified continuation.
Local drift still raises a reconciliation error and exits 1. Adding an upstream
after the snapshot also requires reconciliation; the old local-only receipt does
not silently become verified.

For branches with an upstream, the existing live remote lookup and tracked/live
SHA comparison remain mandatory. An unchanged matching snapshot returns
`CONTINUATION_MATCH` and exits 0. A changed live remote head, missing tracked
remote branch, or network failure retains the existing error path; this repair
does not claim a fallback for those cases. A handoff remains evidence, never a
distributed writer lock or permission to overwrite another writer.

## Reproduce and validate

Run commands from the candidate checkout root. Requires Python 3.11+, Git with
`git init -b` support, and a POSIX filesystem supporting symlinks and FIFOs.
The unit tests create disposable repositories and a local bare remote; they
need no network, model files or third-party packages.

```sh
python3 -m unittest scripts.tests.test_bamf_writer_handoff -v
python3 -B scripts/check_bamf_flow_control.py
git diff --check
```

Three new local-only regressions failed before the repair with missing-upstream
errors. The initial eight-test selection passed: the original four cases, the
three new local-only API/CLI cases, and an unfetched live-remote advance regression.
The latter proves the specific tracked/live remote drift check still rejects
an unfetched advance; it is not an exhaustive proof of every remote failure mode.

Example for an existing local branch without an upstream:

```sh
python3 -B scripts/bamf/writer_handoff.py emit \
  --issue 810 --epoch B06-810-20261103 --worktree /path/to/worktree > /tmp/handoff.json
python3 -B scripts/bamf/writer_handoff.py verify \
  --payload /tmp/handoff.json --worktree /path/to/worktree
```

The first command writes JSON and exits 0; the second prints `UNVERIFIED` and
exits 2 until remote verification becomes available through separately reconciled
state. A fresh receipt is required after that state changes.

The actual preserved #810 worktree now emits its local commit and dirty
fingerprint without configuring an upstream or pushing its uncommitted work.
Its source-selection and prediction-owner acceptance remain separate holds.
