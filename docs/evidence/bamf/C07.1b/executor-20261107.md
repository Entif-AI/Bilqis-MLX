## Implemented executor

`runtime.jit_adoption.PreparedSuccessorRuntime` names the one serialized learner
lane that the existing prepared-successor transaction consumes. Constructing the
record grants no admission authority.

`execute_prepared_successor_adoption(...)` performs the concrete C07.1b executor
sequence:

1. replay the exact native proposal against current frontier/evidence/plan and
   checkpoint through `resolve_ready_candidate(...)`;
2. revalidate current source and answer implementation descriptors;
3. re-read the admitted Factory release and saved school checkpoint from the run
   immediately before commit;
4. reject release/checkpoint drift before entering the transaction; and
5. consume the existing `_adopt_prepared_successor(...)` owner, returning the
   updated serialized runtime state without any optimizer update.

The public Atlas policy still stages an otherwise authorized disposable lease.
Its hold reason is now `ACCEPTED_RUN_AUTHORITY_UNAVAILABLE`, not the obsolete
`ADOPTION_EXECUTOR_UNAVAILABLE`: the executor exists, while production run
authority does not.
